# 任意 job 的周期运行

新计划统一进入应用的持久化调度器。macOS 使用 launchd 保持执行器常驻，执行器每 10 秒从 SQLite 领取到期任务，并启动独立 worker 调用研究引擎。关闭页面、退出 App 或重启 Web 都不会终止这个调度器。

## 使用

管理员可以在「新建 Job」勾选「创建后自动周期运行」，选择频率和时间；也可以在「周期调度」为已有 job 创建计划。新建 job 和计划一起返回成功，无法安装或确认执行器心跳时明确报错，不会留下看似启用的计划。模板 YAML 中的 `schedule` 仍只是提示，不会因导入模板而自动启动收费任务。

每个 job 支持一个计划。选择已有计划的任务会进入编辑；禁用的 job 无法创建计划。中文名称、分类目录、路径中的空格均可使用。执行器按参数数组调用 Python，无需填写或拼接 shell 命令。API 密钥从项目 `.env` 读取，不能填在调度表达式中。

五字段 cron 支持每天、工作日、每周、每月、固定间隔和高级表达式；保存前展示接下来三次执行。默认使用服务器时区，也可以指定 IANA 时区，如 `Asia/Shanghai`。不存在的月末日期跳过；日期与星期同时受限时按 cron 的 OR 语义，夏令时按该时区的真实时刻计算。

## 执行约定

| 情况 | 行为 |
| --- | --- |
| 首次创建 | 从下一个未来时刻开始，不追溯创建前的历史 |
| 休眠、关机或执行器中断 | 默认合并为最新一次补跑；也可选择跳过逾期一分钟以上的时刻 |
| 同一 job 耗时超过周期 | 当前运行或重试完成前不启动第二份；完成后合并处理最新到期时刻 |
| 模型、网络或执行进程失败 | 默认最多重试 2 次，间隔 1 分钟、5 分钟；可设 0–5 次 |
| job 被禁用、删除或预算阻止 | 记录未执行的原因；禁用/预算问题不进行短间隔重试，下个周期会重新检查 |
| 暂停或删除计划 | 取消尚未开始的执行及重试；已经运行的任务继续完成 |
| 编辑计划 | 保持启停状态，取消旧配置的待执行任务，使用新配置的下次时间 |
| 恢复暂停计划 | 从下一个未来时刻开始，不补跑暂停期间的任务 |
| 删除 job | 同时移除计划；正在执行时拒绝删除，历史保留 |

计划、到期时刻、每次尝试与结果保存在 `state/schedules.db`。唯一键和事务防止重复领取，worker 使用进程锁和可续期租约；失联后只回收已经释放进程锁的任务。全局最多两个 worker 并行。研究引擎按解析后的 job 路径加锁，手动与周期执行共用锁；活跃进程的锁不会仅因运行时间长而被抢走，死亡进程的锁可以回收。

成功以研究引擎实际生成报告为准。记录包含计划时刻、开始时间、尝试次数、失败原因和报告绝对路径。执行器心跳与最近执行结果分别展示，执行器在线不代表模型一定成功。调度采用故障后可重试的执行语义；如果进程在报告写出后、结果落库前崩溃，恢复时可能重新执行一次，并不承诺外部副作用的 exactly-once。

## 安装与运维

创建计划时自动检查执行器；也可以提前安装：

```bash
python scripts/install_scheduler.py
```

每个 state 目录有独立的 `com.arec.scheduler.<hash>` LaunchAgent。配置使用绝对 Python 和工作目录，并由 launchd 自动恢复。搬动项目或更换虚拟环境后重新运行安装脚本。日志：`logs/scheduler-host.err.log`、`logs/scheduler.log`、`logs/schedules/<run_id>.log`。计划和历史不在 Web 内存中，重启不丢失。

macOS 需要电脑开机且用户会话可用；关机或休眠期间不能准点执行，恢复后才补跑。严格要求全天准点的执行端应部署在常开服务器。其他平台可用 systemd/容器服务托管 `scripts/dispatch_schedules.py`（工作目录为项目，使用同一 Python、配置和持久化 state 目录）；本次仅自动安装 macOS launchd。执行器离线时，创建/恢复计划会报错，不能把“保存了时间”当作调度已经可用。

已有 cron 保留编辑兼容，情报矩阵的每日和半小时补偿仍通过 `ensure_round.py` 运行，在页面只读显示。新计划不再写入 cron，不自动迁移旧触发器。将同一 job 从旧 cron 改为托管计划时，应先暂停旧计划；自定义 shell 和外部触发器无法全部自动识别。

## 验证

自动化测试覆盖：持久化、并发抢占与限流、时区、离线合并/跳过、有限重试、暂停与修改的版本隔离、崩溃回收、预算阻止、删除联动、权限、创建回滚和页面流程。

真实 macOS 验收脚本：

```bash
python scripts/verify_managed_scheduler.py
```

它创建临时中文 job 和含空格的工作目录，通过本地模拟的 OpenAI 兼容 HTTP 接口运行真实研究引擎，不消耗线上模型额度。测试连续两个自然分钟触发、执行器停机错过一次后的补跑、launchd 自动重启与暂停计划持久化；没有 Web 服务参与。最后核对三个报告内容，写出 `acceptance.json`，删除临时 LaunchAgent。2026-09-25 已在本机通过此完整验收。
